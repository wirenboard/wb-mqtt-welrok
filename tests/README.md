# Описание тестов и инструкция по запуску

Этот файл описывает тесты в репозитории и шаги для локального запуска.

Кратко:

- Тесты находятся в `tests/test_lifecycle.py`.
- MQTT-брокер, термостат и сеть не нужны.
- Тесты запускаются при сборке пакета (pybuild, `debian/rules`) с зависимостями из Debian-пакетов
  `Build-Depends` — теми же, что пакет получает на контроллере. `DEB_BUILD_OPTIONS=nocheck`
  отключает прогон.

## Описание тестов

### `tests/test_lifecycle.py`

Тестирует жизненный цикл сервиса по гайдлайну WB-сервисов. Брокер и термостат не нужны: paho заменён на `MagicMock`, конфиг проходит через настоящую схему из репозитория.

- Коды выхода: 0 по сигналу, 2 при отвергнутом брокером логине, 6 при отсутствующем или невалидном конфиге (включая неверный URL брокера), 7 когда ни у одного устройства нет `device_id`; `main()` возвращает код клиента
- URL брокера по умолчанию — unix-сокет локального mosquitto; транспорт paho (unix, tcp, websockets) выбирается по схеме URL
- Повторные попытки подключения к недоступному брокеру: подключение уходит в сетевой поток paho, ничего не подключается синхронно
- Восстановление после переподключения: потеря связи не останавливает сервис, в обработчике подключения переиздаются все активные устройства — meta, последние значения контролов и подписки на команды
- Завершение по SIGINT/SIGTERM: остановка задач и выход с кодом 0

Четыре теста асинхронные (`@pytest.mark.asyncio`), для них нужен плагин `pytest-asyncio` — без него pytest их не выполняет. Запуск:

```bash
python -m pytest tests/test_lifecycle.py -q
```

## Тестирование

### Подготовка окружения:

Пакет использует системные зависимости, поэтому проще всего поставить их из Debian (trixie):

```bash
sudo apt install python3-aiohttp python3-jsonschema python3-paho-mqtt python3-pytest python3-pytest-asyncio
```

Либо в виртуальном окружении с теми же версиями, что в trixie:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install "aiohttp==3.11.16" "jsonschema==4.19.2" "paho-mqtt==2.1.0" pytest "pytest-asyncio==0.25.1"
```

### Запуск тестов:

- Запустить все тесты:

```bash
pytest -q
```

- Запустить тесты в конкретном файле:

```bash
pytest tests/test_lifecycle.py -q
```

### Интерпретация результатов:

При запуске pytest выводит статистику в формате:

```
23 passed in 0.33s
```

**Статусы:**
- `passed` — тесты прошли успешно ✓
- `failed` — тесты упали, требуется исправление (pytest покажет трейсбек с деталями ошибки)
- `skipped` — тесты пропущены
- `warnings` — предупреждения (не критично, но можно изучить; обычно это deprecation warnings из зависимостей)

**При падении теста:**
1. Pytest покажет полный трейсбек с местом ошибки
2. Обратите внимание на секцию `AssertionError` — там указано, что именно не совпало с ожиданием
3. Используйте `-s` для вывода логов/принтов из теста для детальной отладки
4. Используйте `-k test_name` для запуска только конкретного упавшего теста

**Пример успешного прогона:**
```bash
$ pytest -q
.......................                                  [100%]
23 passed in 0.33s
```

### Параметры полезные при отладке:

- `-q` — компактный вывод;
- `-s` — не подавлять вывод в stdout/stderr (полезно для отладочных print/log);
- `-k <expr>` — запуск тестов, имена которых соответствуют выражению `expr`;
- `--maxfail=1` — остановить после первой неудачи.

### Покрытие (опционально):

```bash
pip install coverage
coverage run -m pytest
coverage report -m
```

### Полезные команды CI-стиля:

```bash
# компактный запуск в CI
pytest --maxfail=1 --disable-warnings -q
```
